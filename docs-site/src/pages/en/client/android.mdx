# Android client

The Android application embeds KnotRoute through a gomobile AAR and does not require a separately installed daemon.

## Recommended onboarding

1. Obtain a QR/deep-link from KnotRoute Control.
2. Open the `knotroute://join?...` URI.
3. Review the Network ID and Beacon list.
4. Save the network profile.
5. Connect.
6. Install the local CA through Android's system UI if `.knot` HTTPS is required.

## Network profiles

Multiple profiles allow separate Production, Test, Home or Lab overlays on the same device.

## Browser

The embedded browser sends `.knot` traffic through the local KnotRoute proxy. The application does not require `VpnService` or occupy the system VPN slot.

## Local CA

Android requires user interaction to add a user CA. TLS errors are treated as failures rather than bypassed.

## Troubleshooting

Check Network ID, Beacon reachability, Internet connectivity, foreground service status, system time and application diagnostics.

## Runtime lifecycle

The foreground service owns the embedded core. After profile changes it performs an ordered stop/start and the Activity reapplies WebView proxy override only after the new core generation is ready. The UI also applies system-bar/display-cutout insets for API 36 edge-to-edge layouts. Circuit hops remain under Advanced settings; ordinary onboarding only needs profile name, Network ID and Beacon HTTP(S) URLs.
