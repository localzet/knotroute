# KnotRoute documentation

KnotRoute is a self-hosted overlay network for services with cryptographic `.knot` identities, multi-hop circuits, distributed discovery, and embeddable clients.

<Callout title="Start with a task">You do not need to learn the protocol first. Pick what you need to do: connect a client, publish a service, operate a network, or embed KnotRoute into an application.</Callout>

## What KnotRoute solves

A common case is an application that should remain private to a host or Docker network while being reachable by authorized application users through a KnotRoute service address.

```text
client
  │ .knot
  ▼
KnotRoute client
  │
  └─ circuit ── relay ── rendezvous ── service ── app:8080
```

A published service has its own service identity, so its canonical address can survive a host migration when the private identity is preserved.

## What KnotRoute does not replace

KnotRoute is not a general-purpose VPN and does not provide public-Internet exit nodes. It also does not replace application authentication, firewalls, backups, or normal TLS for an ordinary public hostname.

<Callout type="warning" title="Transport privacy is not authorization">`network_id` separates overlays but is not a password. Restricted published services still need application-layer authentication.</Callout>

## Project components

| Component | Purpose |
| --- | --- |
| `knotroute` | node/CLI, relay, local gateways and dashboard |
| `knotroute-desktop` | Windows tray and system integration |
