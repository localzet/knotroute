# Linux и macOS

На Linux/macOS KnotRoute можно использовать как CLI node с локальными SOCKS5/HTTP gateways. Это удобный вариант для workstation, сервера разработки и автоматизированных тестов.

## Инициализация

```bash
knotroute init --config ~/.config/knotroute/knotroute.json
knotroute doctor --config ~/.config/knotroute/knotroute.json
knotroute run --config ~/.config/knotroute/knotroute.json
```

## Подключение к сети

Импорт invitation:

```bash
knotroute invite import \
  --config ~/.config/knotroute/knotroute.json \
  --file network.knotinvite
```

Либо задайте Network ID/Beacon вручную в config.

## SOCKS5

Типичный endpoint:

```text
127.0.0.1:9477
```

Приложение должно передавать `.knot` hostname самому proxy. Если оно сначала делает обычный DNS lookup, `.knot` не разрешится публичным DNS.

Для `curl` можно использовать SOCKS hostname resolution:

```bash
curl --socks5-hostname 127.0.0.1:9477 http://example.knot/
```

## HTTP proxy

Типичный endpoint:

```text
127.0.0.1:9478
```

```bash
curl -x http://127.0.0.1:9478 http://example.knot/
```

Для браузера задайте HTTP/HTTPS proxy вручную или используйте platform integration, если она поддерживается вашей сборкой.

## Запуск как service

Для постоянного Linux node используйте systemd unit из `packaging/systemd/` либо собственный unit с отдельным непривилегированным пользователем и persistent data directory.

Не запускайте dashboard на `0.0.0.0`, если он не находится за отдельной аутентификацией и trusted network.
