# KnotRoute: документация

KnotRoute — self-hosted overlay-сеть для сервисов с криптографическими `.knot`-идентичностями, multi-hop circuits, распределённым discovery и возможностью встроить клиент прямо в приложение.

## Что решает KnotRoute

Типичная задача: приложение слушает только внутри сервера или Docker network, но его нужно безопасно открыть другим KnotRoute-клиентам без публикации прикладного порта в Интернет.

```text
клиент
  │
  │ .knot
  ▼
KnotRoute client
  │
  ├─ discovery / directory
  │
  └─ onion-style circuit ── relay ── rendezvous ── service
                                              │
                                              ▼
                                          app:8080
```

Сервис получает самостоятельную service identity. Поэтому его canonical address может сохраняться при переносе между серверами — нужно сохранить приватный identity-файл.

## Что KnotRoute не заменяет

KnotRoute не является универсальным VPN и не предоставляет выход в обычный Интернет. Он также не заменяет прикладную аутентификацию, firewall, резервные копии или TLS для обычного публичного домена.

<Callout type="warning" title="Не путайте приватность транспорта с авторизацией">`network_id` разделяет overlay-сети, но не является паролем. Для закрытого опубликованного сервиса используйте аутентификацию самого приложения.</Callout>

## Компоненты проекта

| Компонент | Для чего нужен |
| --- | --- |
| `knotroute` | основной node/CLI, relay, локальные proxy и dashboard |
| `knotroute-desktop` | Windows tray и системная интеграция |
| Android client | мобильный клиент и встроенный `.knot` browser |
| `knotroute-beacon` | peer discovery и опциональный bootstrap relay |
| `knotroute-sidecar` | публикация существующего TCP/Docker-сервиса |
| `knotroute-control` | управление инфраструктурой, onboarding и deployment jobs |
| `knotroute-agent` | управляемый агент на Docker-host, соединяющийся с Control наружу |
| `knotroute-docs` | этот self-hosted сайт документации |
| Go SDK / Android AAR | встраивание KnotRoute в собственные приложения |
