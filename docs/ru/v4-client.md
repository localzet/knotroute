# Клиент KnotRoute v4

v4 перестаёт быть «демоном с веб-панелью». На Windows основной клиент — один `KnotRoute.exe`, внутри которого работают overlay-node, tray и нативный интерфейс.

## Разделы Windows-клиента

- **Главная** — состояние соединения, узел, пользователь, текущий транспорт.
- **Чаты** — контакты и подписанные сообщения `ku_...` пользователей.
- **Каталог** — реально обнаруженные сервисы; это не сканирование всего адресного пространства.
- **Сеть** — Network ID, Beacon и основные настройки подключения. Необязательные параметры транспорта скрыты отдельно.
- **Разработчикам** — `kn_`, `kr_`, `ku_`, `ks_`, `.knot`, node-bound services, canonical service identities, алиасы, публикация Docker-сервисов и диагностика.
- **Настройки** — профиль, Root CA, автозапуск и локальные данные.

## Android

В Android-клиенте больше нет встроенного браузера. Каталог и другие части приложения открывают `.knot` через системный `ACTION_VIEW`, то есть пользователь выбирает обычный браузер.

Текущая browser integration использует Android VPN HTTP proxy и требует Android 10+. Это совместимый промежуточный механизм: некоторые приложения и браузеры могут игнорировать рекомендованный Android proxy. Полная packet-level интеграция потребует tun2socks.

## Мессенджер alpha

У пользователя есть отдельная `ku_...` identity. Профиль и сообщения подписываются Ed25519. Для online-соединения клиент публикует внутренний сервис `kr-chat` и передаёт сообщения через KnotRoute circuits.

Это уже рабочий transport сообщения между двумя online-узлами, но в alpha.1 ещё не подключены offline mailbox, multi-device sync, группы, каналы и звонки.
